# ADHD Screening from Parent, Teacher and Attainment Data

MSc Data Science project: an end-to-end pipeline that simulates realistic school records, trains a neural-network classifier to flag students who may need an ADHD assessment, explains which factors drive the prediction, and serves it through a small web app.

> **All data in this repository is synthetic.** It was generated by `project_part_1_dataset.py` to mimic the structure of the Vanderbilt ADHD rating scales and school attainment marks. No real children's data was used.

**Skills shown:** synthetic data design · Python (pandas, NumPy, SciPy) · PyTorch · Restricted Boltzmann Machine feature learning · cross-validated model selection · Random Forest feature importance · Flask deployment

---

## Results

Held-out test set of 2,000 students (20%, stratified), never used in training:

| Metric | Value |
|---|---|
| Accuracy | 96.8% |
| Precision (ADHD) | 0.88 |
| Recall (ADHD) | 0.84 |
| F1 (ADHD) | 0.86 |
| ROC AUC | 0.92 |

Only 11.6% of students are in the ADHD class, so a model that always answered "no ADHD" would already score 88% accuracy. **Precision, recall and F1 on the ADHD class are the meaningful numbers:** the model finds 84% of ADHD cases, and 88% of the students it flags are true cases.

**Did the RBM help?** Not on this data. The same neural network trained directly on the scaled features reached F1 0.87 (precision 0.97, recall 0.79) against 0.86 with RBM features. The RBM version finds more ADHD cases (higher recall) at the cost of more false alarms. For a screening tool, catching more cases is usually the better trade-off, but a simpler model without the RBM is a fair alternative.

**Most influential factors** (Random Forest feature importance): parent-rated school performance, average maths mark, teacher-rated school performance and average English mark, ahead of individual behaviour questions.

## How it works

| Step | Script | What it does |
|---|---|---|
| 1. Data | `project_part_1_dataset.py` | Generates 10,000 student records: 53 parent and 53 teacher rating-scale answers, 10 English and 9 maths marks, summary statistics per subject, and 2% label noise to mimic real-world error. Saves charts comparing the two groups. |
| 2. Model | `project_part_2_rbm_fnn.py` | Scales features, learns compressed features with a Restricted Boltzmann Machine, picks the RBM size (32–512 hidden units) by 5-fold cross-validation, then trains a feed-forward neural network on top. Compares against the same network trained on the raw features. |
| 3. App | `project_part_3_adhdpredictionapp.py` | Flask web form: enter a student's answers and marks, get a screening result with a probability. |
| 4. Explain | `project_part_4_feature_importance.py` | Random Forest feature importance to show which inputs matter most. |

Shared file locations are set in `config.py`.

## How to run

```bash
git clone https://github.com/somynt/Project_DataScience.git
cd Project_DataScience
pip install -r requirements.txt

python project_part_1_dataset.py              # regenerate the synthetic data (optional, data is included)
python project_part_2_rbm_fnn.py              # train and evaluate (saves rbm_model.pth, fnn_model.pth, scaler.pkl)
python project_part_3_adhdpredictionapp.py    # web app at http://127.0.0.1:5000
python project_part_4_feature_importance.py   # feature importance chart
```

The trained models are included, so the app works without retraining.

**In Google Colab:** to keep files in Google Drive, set the folder before running:

```python
import os
os.environ["ADHD_PROJECT_DIR"] = "/content/drive/MyDrive/Project_ADHD"
```

For a public link to the app from Colab, also set `NGROK_AUTHTOKEN` to your own ngrok token. Never paste the token into the code.

## Limitations

- The data is simulated, so these results show the method works on data with the assumed structure. They do not show clinical accuracy. Validating on real, properly governed school or NHS data would be the essential next step.
- This is a screening aid, not a diagnosis. The app tells users to see their GP.
- `student_id` was left in the training features. It is random and carries no signal, but it should be removed and the model retrained.
